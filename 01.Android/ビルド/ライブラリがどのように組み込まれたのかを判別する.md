# ライブラリがどのように組み込まれたのかを判別する

既存のプロジェクトで、ライブラリを更新する際に、ライブラリがどのように組み込まれたのかを確認したい場合があります。

手動でダウンロードしたライブラリがプロジェクト内に配置されたのか、それとも、リモートリポジトリから自動的にダウンロードされたのかによって、ライブラリの更新方法も変わってきます。

その際に、参考になる方法について説明します。


## ケース１： .aar ファイルがプロジェクト内に配置されている場合

```
app/libs/mylibrary.aar
```

このようにプロジェクト内（多くは `libs/` フォルダ）に `.aar` が配置されている場合は、自分自身、または他の開発者が手動でダウンロードして追加したものである可能性が高いです。

Gradle の build.gradle.kts では、以下のように指定されています。

```kotlin
dependencies {
    implementation(files("libs/mylibrary.aar"))
}
```

これはリモートリポジトリではなく、ローカルファイルを直接参照していることを意味します。よって、この場合は「手動で組み込まれたライブラリ」です。


## ケース２： .aar ファイルが Gradle のキャッシュ内にある場合

Gradle は、リモートリポジトリ（MavenCentral、Google、JitPack など）から .aar をダウンロードすると、それをローカルキャッシュに保存します（通常は以下のようなパス）。

```
~/.gradle/caches/modules-2/files-2.1/...
```

これらはアプリのプロジェクトフォルダ内ではなく、Gradle の管理下で自動的に保存されるものです。そのため、通常は IDE からは .aar ファイルは見えません。この場合は「リモートリポジトリから自動ダウンロードされたライブラリ」です。


## ケース３：一部のビルドシステムや SDK が自動的に .aar を同梱する場合

例えば、外部 SDK（広告 SDK や地図 SDK など）が Gradle plugin によって内部で .aar を展開することもあります。

しかし、それでも通常、`.aar` は `build/` 以下の一時フォルダに配置され、開発者が直接管理する場所（ `app/` 直下など）には置かれません。
