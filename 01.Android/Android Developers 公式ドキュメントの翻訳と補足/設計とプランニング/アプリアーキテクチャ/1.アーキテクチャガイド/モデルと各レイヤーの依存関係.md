# モデルと各レイヤーの依存関係

最新の Android アプリ開発では、 UI レイヤー / ドメインレイヤー / データレイヤーの 3 層アーキテクチャが推奨されています。

各レイヤーの依存関係は、公式ドキュメント ( [アプリアーキテクチャについて](./1.アプリアーキテクチャについて.md) ) を見る限りでは、 `UI レイヤー -> ドメインレイヤー -> データレイヤー` の関係にあることが示されています。確かにこれは正しい依存関係なのですが、モデルを含めて考えた場合、一部、依存関係が逆転する場合もあるため、その点について解説します。

## 公式アーキテクチャでは説明されていない部分

公式アーキテクチャで説明されていない部分は以下です。

- `データレイヤーのクラス -> ドメインモデル` の依存は OK
- `ドメインレイヤーのクラス -> データモデル` の依存は NG

ドメインレイヤー内のクラスが、データモデルに依存した場合について考えます。

データモデル ( DB のテーブル定義など) が変更された際に、ドメインレイヤーのクラスに影響が出ることになります。ドメインレイヤーの責務は、アプリのビジネスの本質に関することだけに関心があるべきです。したがって、単なるデータ構造の変更によって、ドメインレイヤーに修正が及ぶのは避けるべきです。よって、この依存関係は適切ではないことがわかります。

次に、データレイヤー内のクラスが、ドメインモデルに依存した場合について考えます。

データモデル ( DB のテーブル定義など) が変更された際に、その修正がデータレイヤー内に収まることができます。

UI モデルとドメインモデルについても、同様に考えることで、推奨アーキテクチャの依存関係が適切であることがわかるはずです。


## モデルの依存関係の正体

さて、ここまで説明してきた、このモデルとロジッククラスの依存関係こそが、巷で人気の「クリーンアーキテクチャ」の正体です。

クリーンアーキテクチャの概念では、円の中央にドメインモデルが存在し、外側の円には、 UI 層やデータアクセス層が存在しています。そして、円の外側から内側への依存関係が良い依存関係であるとされています。
