### DensityMode に変換する

```kotlin
enum class DensityMode {
    Dense, // タブレット / Desktop など、情報密度重視の場合
    Normal, // スマホの標準設定の場合
    Spacious // 視力の弱い方が文字サイズを上げた場合（アクセシビリティも同時に確保）
}

fun WindowWidthSizeClass.toDensityMode(): DensityMode =
    when (this) {
        WindowWidthSizeClass.Compact -> DensityMode.Spacious
        WindowWidthSizeClass.Medium -> DensityMode.Normal
        WindowWidthSizeClass.Expanded -> DensityMode.Dense
        else -> DensityMode.Normal
    }
```

【注意】: WindowWidthSizeClass を解決するためには、以下の依存関係を定義する必要があります。

```
androidx-material3-window-size = { group = "androidx.compose.material3", name = "material3-window-size-class" }
```

ここがポイントです。

- Compact = 余白を大きく
- Expanded = 余白を詰める

なぜなら、

- スマホは移動中に操作することが多いため、視線や手元がぶれやすく、視認性の良さや誤タップ防止が求められます。
- タブレットは、止まって操作することが多いため、上記が起こりにくい。

よって、画面が広いから **「余白を増やす」のではなく、情報量を増やす** のが本質です。

ただし、大画面になっても、意味を分けたい境界では、きちんんと余白を確保するという考え方は同じです。特に意識するべきポイントは、タブレットでマルチペイン表示する場合です。「リスト + 詳細」のマルチペイン画面を表示する際、リストペイン内部と詳細ペイン内部は、それぞれ高密度な余白にしますが、リストと詳細の境界は低密度な余白を設定します。 (ただし、実装で実際に DensityMode.Density と DensityMode.Spacious をわざわざ切り替える必要はなく、 s , m , l などの意味をあらわす Spacing の xl を使ってペインを区切れば十分です。サンプルコードは [Compose のマルチペイン.md](./Compose%20のマルチペイン.md) にあります。) 


### CompositionLocal で流す

```kotlin
val LocalDensityMode = compositionLocalOf { DensityMode.Normal }

@Composable
fun AppRoot(
    densityMode: DensityMode,
    content: @Composable () -> Unit
) {
    CompositionLocalProvider(
        LocalDensityMode provides densityMode,
        content = content
    )
}
```


### Spacing Token を具体化する

```kotlin
object Spacing {

    // 同一要素内部（icon-text, label-value）
    val xs: Dp
        @Composable get() = when (LocalDensityMode.current) {
            DensityMode.Dense -> 4.dp
            DensityMode.Normal -> 8.dp
            DensityMode.Spacious -> 12.dp
        }

    // 同一グループ内（ListItem 内、Form 項目内）
    val s: Dp
        @Composable get() = when (LocalDensityMode.current) {
            DensityMode.Dense -> 8.dp
            DensityMode.Normal -> 12.dp
            DensityMode.Spacious -> 16.dp
        }

    // グループ間（Card と Card、Form セクション）
    val m: Dp
        @Composable get() = when (LocalDensityMode.current) {
            DensityMode.Dense -> 12.dp
            DensityMode.Normal -> 16.dp
            DensityMode.Spacious -> 24.dp
        }

    // レイアウト構造（Header / Body、Section 区切り）
    val l: Dp
        @Composable get() = when (LocalDensityMode.current) {
            DensityMode.Dense -> 16.dp
            DensityMode.Normal -> 24.dp
            DensityMode.Spacious -> 32.dp
        }

    // 画面構造（Pane 間、画面端マージン）
    val xl: Dp
        @Composable get() = when (LocalDensityMode.current) {
            DensityMode.Dense -> 24.dp
            DensityMode.Normal -> 32.dp
            DensityMode.Spacious -> 48.dp
        }
}
```

### Layout Token を定義する

スペースサイズに意味を持たせることができる。

```kotlin
object LayoutTokens {
    val screenPadding: Dp
        @Composable get() = Spacing.l

    val sectionSpacing: Dp
        @Composable get() = Spacing.m

    val itemSpacing: Dp
        @Composable get() = Spacing.s
}
```


### Layout 側で使用する

```kotlin
Column(
    modifier = Modifier.padding(LayoutTokens.sectionSpacing)
) {
    PrimaryButton(...)
}
```

Component は Dense / Spacious を一切知らなくてよいところがポイント。


### TouchTarget Token を定義する

フォントサイズを大きくするユーザーは、視力が弱いため、タップ可能領域も大きくすることで Accessibility を改善する。

```kotlin
enum class FontScaleMode {
    Normal,
    Large,
    ExtraLarge,
    Accessibility
}

@Composable
fun currentFontScaleMode(): FontScaleMode {
    val fontScale = LocalDensity.current.fontScale
    return when {
        fontScale <= 1.0f -> FontScaleMode.Normal
        fontScale <= 1.3f -> FontScaleMode.Large
        fontScale <= 1.6f -> FontScaleMode.ExtraLarge
        else -> FontScaleMode.Accessibility
    }
}
```

### TouchTarget Token を Spacing Token に組み込む

```kotlin
object Spacing {
    // タッチ可能領域に使用する余白
    val touchTarget: Dp
        @Composable get() = when (currentFontScaleMode()) {
            FontScaleMode.Normal -> 48.dp
            FontScaleMode.Large -> 52.dp
            FontScaleMode.ExtraLarge -> 56.dp
            FontScaleMode.Accessibility -> 64.dp
        }
}
```


### TouchTarget Token を使用する

リストアイテムの高さの指定に使用する例 : 

```kotlin
@Composable
fun SettingsItem(
    title: String,
    onClick: () -> Unit
) {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .height(Spacing.touchTarget)
            .clickable(onClick = onClick)
            .padding(horizontal = Spacing.m),
        verticalAlignment = Alignment.CenterVertically
    ) {
        Text(text = title)
    }
}
```

アイコンの幅と高さに使用する例 :

```kotlin
@Composable
fun IconAction(
    icon: ImageVector,
    onClick: () -> Unit
) {
    Box(
        modifier = Modifier
            .size(Spacing.touchTarget)
            .clickable(onClick = onClick),
        contentAlignment = Alignment.Center
    ) {
        Icon(icon, contentDescription = null)
    }
}
```


## スペーストークンの具体例

これはそのまま実務で使えます。

### xs（Extra Small）

- 用途
  - 同一コンポーネント内部の最小間隔
- 具体例
  - アイコンとテキストの間
  - ListItem 内の行間
  - Button 内の icon–label 間

xs は、 **「意味的に一体の要素の境界」** に使用します。


### s（Small）

- 用途
  - 同一グループ内の要素間隔
- 具体例
  - フォームのラベルと入力欄
  - カード内の項目同士
  - セクション内の縦並び要素

s は、 **「同じ話題だと一目でわかる境界」** に使用します。


### m（Medium）

- 用途
  - グループとグループの区切り
- 具体例
  - フォームの項目ブロック間
  - List セクション同士の間
  - Card と Card の間（同カテゴリ）

m は、 **「話題が切り替わる境界」** に使用します。


### l（Large）

- 用途
  - 画面構造レベルの区切り
- 具体例
  - ヘッダーと本文
  - 検索エリアと結果一覧
  - ナビゲーションとコンテンツ

l は、 **「レイアウト構造の境界」** に使用します。


### xl（Extra Large）

- 用途
  - 画面全体の呼吸・余白
- 具体例
  - 画面端マージン
  - セクションの外側余白
  - マルチペイン間の距離

xl は、 **「情報ブロック同士を明確に分離する境界」** に使用します。
