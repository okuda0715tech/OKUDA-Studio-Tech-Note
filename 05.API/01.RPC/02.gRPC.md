# gRPC

gRPC は、 Google が提供している RPC で、クライアントサーバー間の通信を関数呼び出しによって実現する方法です。

gRPC は、 REST API を使わずにクライアントサーバー間の通信を実現する方法の一つです。

型がしっかりと定義されるため、未定義の関数呼び出しなどのミスが減るというメリットなど、メリットもありますが、 Android アプリ開発においては、 REST API を使うのが一般的です。


## REST API と gRPC の比較

- REST API
  - URL / JSON
  - ブラウザと相性良い
  - デバッグしやすい
  - だれでも理解しやすい

- gRPC
  - 関数 / protobuf（バイナリ）
  - 高速・省帯域
  - 双方向ストリーミングあり
  - 型安全（サーバとクライアントのズレが起きにくい）


## gRPC の実際の流れ

```
アプリエンジニアが呼ぶ関数
   ↓（自動生成されたクライアントコード）
バイナリ化（protobuf）
   ↓
HTTP/2 で送信（RESTではない）
   ↓
サーバ側の gRPC ライブラリが受信
   ↓
protobuf をデコード
   ↓
サーバ側関数を実行してレスポンス返却
```

この「関数定義」を .proto ファイルに書きます。


## Android で gRPC を使う最小のサンプル

### 1. .proto ファイルを作る（API 定義）

`app/src/main/proto/hello.proto：`

```proto
syntax = "proto3";

package hello;

// リクエストメッセージ
message HelloRequest {
  string name = 1;
}

// レスポンスメッセージ
message HelloReply {
  string message = 1;
}

// gRPC サービス（つまり “関数”）
service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}
```

ここで書かれたのは “REST API ではなく 関数 そのもの” です。


### 2. Gradle 設定（Kotlin + gRPC 用）

`build.gradle`

```gradle
plugins {
    id 'com.android.application'
    id 'org.jetbrains.kotlin.android'
    id 'com.google.protobuf' version '0.9.4'
}

android {
    namespace "com.example.grpcsample"
}

dependencies {
    implementation "io.grpc:grpc-okhttp:1.62.2"
    implementation "io.grpc:grpc-protobuf-lite:1.62.2"
    implementation "io.grpc:grpc-stub:1.62.2"
}

protobuf {
    protoc {
        artifact = "com.google.protobuf:protoc:3.25.1"
    }
    plugins {
        grpc {
            artifact = "io.grpc:protoc-gen-grpc-java:1.62.2"
        }
    }
    generateProtoTasks {
        all().each { task ->
            task.plugins {
                grpc {}
            }
        }
    }
}
```

ビルドすると .proto から以下のクラスが自動生成されます：

- GreeterGrpc
- HelloRequest
- HelloReply

これが “関数を呼び出すためのクライアント” になります。


### 3. Android から gRPC 呼び出し

```kotlin
import hello.GreeterGrpc
import hello.HelloRequest
import io.grpc.ManagedChannelBuilder

suspend fun callGrpc() {
    // gRPC チャンネル作成（HTTP/2）
    val channel = ManagedChannelBuilder
        // サーバーのホスト名とポートを指定 (ホスト名の代わりに IP でも OK )
        .forAddress("example.com", 50051)
        // TLS を使わない場合の指定 (開発環境用)
        .usePlaintext()
        .build()

    // 自動生成された stub（クライアント）
    val stub = GreeterGrpc.newBlockingStub(channel)

    val request = HelloRequest.newBuilder()
        .setName("Okuda")
        .build()

    val reply = stub.sayHello(request)

    println("サーバーからのメッセージ: ${reply.message}")

    channel.shutdown()
}
```

Android のコードは REST URL も JSON も扱いません。
ただの関数呼び出しに見えます。

サーバーの指定には、 URL ではなく ホスト + ポート を使用します。

関数名でルーティングされるため、 REST のように `/api/hello` のようなパスは不要です。


### サーバ側（参考：Kotlin or Java）

サーバー側にもアプリ側に配置した .proto ファイルと同じファイルを配置する必要があります。

```kotlin
class GreeterService : GreeterGrpc.GreeterImplBase() {
    override fun sayHello(
        req: HelloRequest,
        responseObserver: StreamObserver<HelloReply>
    ) {
        val reply = HelloReply.newBuilder()
            .setMessage("Hello, ${req.name}")
            .build()

        responseObserver.onNext(reply)
        responseObserver.onCompleted()
    }
}
```
