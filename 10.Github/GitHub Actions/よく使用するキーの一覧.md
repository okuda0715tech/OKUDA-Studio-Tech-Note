# よく使用するキーの一覧

ここでは **「実務でまず押さえるべき GitHub Actions が定義している意味（キー）」** を、 **多すぎない・でも全体像が掴める** 粒度で一覧化します。

---

## ワークフロー全体レベル

### `name`

* ワークフローの表示名
* Actions 画面に出る

```yaml
name: Android CI
```

---

### `on`

* **いつ実行されるか（トリガー）**

```yaml
on:
  pull_request:
  push:
    branches: [ main ]
```

よく使うトリガー：

* `push`
* `pull_request`
* `workflow_dispatch`（手動実行）

---

## Job レベル

### `jobs`

* ワークフロー内の **実行単位の集合**

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
```

---

### `runs-on`

* **どの実行環境（Runner）で動かすか**

```yaml
runs-on: ubuntu-latest
```

代表例：

* `ubuntu-latest`（Android ではほぼこれ）
* `macos-latest`
* `windows-latest`

---

### `needs`

* **Job の依存関係**

```yaml
needs: test
```

「 test という Job が成功したら build という Job を実行する」を表現できる。

Job は本来、独立した実行単位であり、依存関係を指定しなかった場合は、並列で実行される。

---

以下は、 build が test に依存している例です。

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - run: ./gradlew test

  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - run: ./gradlew assembleDebug
```

---

## Step レベル

### `steps`

* Job 内で行う処理の並び

```yaml
steps:
  - name: Checkout
    uses: actions/checkout@v4
```

---

### `name`

* Step の表示名（ログが読みやすくなる）

---

### `uses`

* **Action（再利用可能な処理）を使う**

```yaml
uses: actions/checkout@v4
```

公式 Action 例：

* `actions/checkout`
* `actions/setup-java`
* `actions/upload-artifact`

---

### `run`

* **シェルコマンドを実行**

```yaml
run: ./gradlew test
```

複数行も可：

```yaml
run: |
  ./gradlew test
  ./gradlew lint
```

上記は下記と同じです。

```yaml
run: "./gradlew test\n./gradlew lint\n"
```

---

### `with`

* `uses` で使う Action への **引数**

```yaml
with:
  java-version: '17'
```

Action ごとに定義が異なる。

---

### `env`

* **環境変数を定義**

```yaml
env:
  JAVA_HOME: /path/to/java
```

Job / Step 両方で使える。

---

## 条件・制御系（少し中級）

### `if`

* **条件付き実行**

```yaml
if: github.event_name == 'pull_request'
```

例：

* PR のときだけ実行
* main ブランチだけ実行

---

### `timeout-minutes`

* **タイムアウト設定**

```yaml
timeout-minutes: 30
```

---

### `continue-on-error`

* **失敗しても次へ進む**

```yaml
continue-on-error: true
```

Lint を最初に導入するときによく使う。

---

## Artifact / 出力関連

### `uses: actions/upload-artifact`

* **成果物を保存**

```yaml
uses: actions/upload-artifact@v4
```

---

### `name`（Artifact 用）

* Artifact の表示名

---

### `path`

* 保存対象ファイル

```yaml
path: app/build/outputs/apk/debug/*.apk
```

---

### `retention-days`

* Artifact の保存期間

```yaml
retention-days: 7
```

---

## 変数・コンテキスト（重要）

### `secrets`

* GitHub に登録した **秘密情報**

```yaml
secrets.MY_API_KEY
```

---

### `github`

* 実行コンテキスト情報

```yaml
github.ref
github.actor
github.event_name
```

条件分岐でよく使う。

よく使用する `github.*` を以下で例示します。

---

`github.event_name`

```yaml
if: github.event_name == 'pull_request'
```

以下のどれかが入っています。

- `push`
- `pull_request`
- `workflow_dispatch`

---

`github.ref`

```
refs/heads/main
refs/pull/123/merge
```

どのブランチ・PR かを判定できる。

---

`github.sha`

- 実行対象の commit SHA
- 「この APK はどのコードから作られたか」に使える

---

`github.actor`

- 実行をトリガーしたユーザー
- Bot / 人 の判別にも使える

---

`github.repository`

```
owner/repo
```

---

### 実践的な使い方例

- PR のときだけ lint を厳しくする

```yaml
if: github.event_name == 'pull_request'
```

- main ブランチだけ APK を作る

```yaml
if: github.ref == 'refs/heads/main'
```

## Android CI で「まず覚えれば十分」セット

最低限これだけでOKです：

* `name`
* `on`
* `jobs`
* `runs-on`
* `steps`
* `uses`
* `run`
* `with`
* `if`
* `env`
* `actions/upload-artifact`
