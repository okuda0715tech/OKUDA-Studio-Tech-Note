# アクション末尾のバージョンの意味

## まず結論を一文で

```yaml
uses: actions/checkout@v4
```

の `@v4` は、

> **GitHub 上の `actions/checkout` リポジトリに付けられた
> Git のタグ（ref）を指定している**

です。

---

## `@` の正体：Git の ref 指定

GitHub Actions の `uses:` は、内部的には

```text
owner/repo@ref
```

という **Git リポジトリの参照指定**です。

この `ref` には、Git が理解できるものなら何でも指定できます。

### 指定できる ref の種類

* **タグ**（tag）

  * `v4`
  * `v4.1.1`
* **ブランチ**

  * `main`
* **コミット SHA**

  * `a1b2c3d4...`

つまり `@v4` は：

> 「`actions/checkout` リポジトリの
> `v4` という ref を使え」

という意味です。

---

## では `v4` とは何か？

### これは **GitHub Actions の独自構文ではありません**

`v4` は：

* `actions/checkout` リポジトリ側が
* **Git のタグとして付けている名前**

です。

Git の世界ではよくある：

```text
v1
v2
v3
v4
```

という **メジャーバージョンタグ**です。

---

## なぜ「v4」だけ書いていいのか？

### 実は `v4` は「動くタグ」

`actions/checkout` では：

* `v4.0.0`
* `v4.1.0`
* `v4.1.1`

のような **細かいタグ**が存在します。

そのうえで：

* `v4` というタグが
* **常に最新の v4.x.x を指すように更新される**

仕組みになっています。

つまり：

```text
v4 → v4.1.1 → v4.1.2 → …
```

と **中身が進化するタグ**です。

---

## なぜそれが許されているのか？

ここが重要です。

### セマンティックバージョニング前提

`actions/checkout` は：

* **メジャーバージョンが変わるときだけ**

  * 破壊的変更を入れる
* v4 系の中では

  * 後方互換を保つ

という運用をしています。

だから：

* `@v4` → 安全にアップデートされる
* `@v5` → 明確に挙動が変わる

---

## 他の指定方法との比較

### ❌ `@main`

```yaml
uses: actions/checkout@main
```

* ブランチは常に動く
* 破壊的変更が突然入る可能性あり
* **本番 CI では非推奨**

---

### ⚠ `@v4.1.1`

```yaml
uses: actions/checkout@v4.1.1
```

* 完全固定
* 再現性は最高
* ただし：

  * セキュリティ修正が入らない
  * メンテナンスコストが上がる

---

### ✅ `@v4`（推奨）

```yaml
uses: actions/checkout@v4
```

* 後方互換を保った更新を自動で取り込む
* CI が突然壊れにくい
* **公式も推奨**

---

## 「Action のバージョン」とは何を指している？

ここで混乱しやすい点を整理します。

* ❌ OS のバージョンではない
* ❌ コマンドのバージョンでもない
* ❌ GitHub Actions 本体のバージョンでもない

✔ **「その Action の実装コードのバージョン」**

です。

---

## 内部で何が起きているか（イメージ）

1. GitHub Actions が
2. `actions/checkout` リポジトリを
3. `v4` タグが指す commit で
4. checkout して
5. そのコードを Step として実行

つまり **Action もただの Git リポジトリ**です。
