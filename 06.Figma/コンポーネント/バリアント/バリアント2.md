**Figma の Variant（バリアント）** とは、 **「同じコンポーネントの状態違いをまとめて管理する仕組み」** です。

簡単に言うと、

* 通常状態
* 押された状態
* 無効状態

のような **UIのバリエーションを1つのコンポーネントとして整理する機能**です。

---

## 1. 例：ボタンの Variant

例えば Android アプリのボタンを作る場合。

通常はこういう状態があります。

* Default（通常）
* Pressed（押されている）
* Disabled（無効）
* Loading（読み込み中）

Variant を使わない場合：

```
Button_Default
Button_Pressed
Button_Disabled
Button_Loading
```

別コンポーネントとして管理する必要があります。

Variant を使うと：

```
Button
 ├ Default
 ├ Pressed
 ├ Disabled
 └ Loading
```

**1つのコンポーネントセットとして管理**できます。

---

## 2. Figma 上での見え方

コンポーネントセットの中に複数の Variant が入ります。

```
* Component Set
  * Button

* Variant
  * state=default
  * state=pressed
  * state=disabled
```

プロパティとして状態を切り替えられます。

右パネルでは、 State から Variant を選択できます。

```
State
  Default
  Pressed
  Disabled
```

---

## 3. Variant のメリット

### ① コンポーネントが整理される

バラバラにならない。

```
Button
TextField
Switch
```

のようにUI単位で管理できる。

---

### ② 状態切り替えが簡単

配置したコンポーネントを

```
State = Disabled
```

に変更するだけ。

---

### ③ プロトタイプで状態遷移できる

例えば

```
Default → Click → Pressed
Pressed → Release → Default
```

のような **UI挙動の再現**ができる。

---

## 4. Android UI設計でよく使う Variant

Android UIではだいたいこういう分類になります。

**State**

```
default
pressed
focused
disabled
```

**Type**

```
filled
outlined
text
```

**Size**

```
small
medium
large
```

つまり Variant は

```
Button
 ├ state=default, type=filled
 ├ state=pressed, type=filled
 ├ state=disabled, type=filled
 ├ state=default, type=outlined
 └ ...
```

のような **UI状態の組み合わせ管理システム**です。
