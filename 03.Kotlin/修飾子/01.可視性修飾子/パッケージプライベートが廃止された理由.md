# パッケージプライベートが廃止された理由

## 具体例

以下のパッケージ構成があったとします。

```
ui/account/
ui/settings/
ui/dashboard/
ui/util/
```

もし ui/util/ に package-private なメソッドやクラスがあった場合、

- その “package” は ui.util となる
- よって ui.account からはアクセス不可
- ui.settings からもアクセス不可
- ui.dashboard からも不可

つまり、 「 UI 全体で共有したい処理」があっても package-private では “ui パッケージ全体” で共有できない。

だからといって、 ui パッケージ直下にパッケージプライベートのメソッドやクラスを配置すると、 ui 直下に配置されるクラスがどんどんと増えてしまう。どんなに増えても、役割ごとにパッケージを分けたくてもわけられない。その結果、様々な責務のクラスが同じパッケージ内に配置されて、混乱の原因になりうる。
