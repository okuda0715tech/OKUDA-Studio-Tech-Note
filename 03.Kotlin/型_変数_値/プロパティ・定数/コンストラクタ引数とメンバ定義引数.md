# コンストラクタ引数とメンバ定義引数

Kotlin や Java では、以下のような二通のメンバープロパティの定義方法があります。これらの違いについて深堀りします。

```kotlin
class A(var p: Int = 0){

}

class B(){
    var p: Int = 0
}
```


## ① プロパティが「コンストラクタの一部かどうか」

`class A(var p: Int = 0)`

- `p` は プライマリコンストラクタのパラメータ
- 同時に プロパティ

つまり、「このクラスは p を持つものとして定義されている」

```kotlin
A()        // p = 0
A(p = 10)  // OK
```

p は クラスの構成要素そのもの です。

---

`class B() { var p: Int = 0 }`

- p は クラス本体で後から定義されたプロパティ
- コンストラクタとは無関係

```kotlin
B()        // p = 0
// B(p = 10) はできない
```

`p` は、「インスタンス生成後に初期化される内部状態」

という位置づけになります。


## ② 「必須性」「不変条件」を表現できるか

これは設計的にかなり重要です。


### A の場合

```kotlin
class A(var p: Int)
```

- p を 必ず 渡せる
- 「このクラスは p を持たずに存在できない」という制約を表現できる

→ ドメインモデル向き


### B の場合

```kotlin
class B {
    var p: Int = 0
}
```

- 生成時点では p はどうでもよい
- 後から変更される前提の「状態」

→ 状態管理・UI・内部ロジック向き


## ③ data class / equals / toString への影響

これは決定的な違いです。

```kotlin
data class A(var p: Int = 0)
data class B() {
    var p: Int = 0
}
```

### A

p が

- equals
- hashCode
- toString
- copy

に 含まれる


### B

- p は 一切含まれない
- `data class B()` の「データ」は 空

👉 「同じ値かどうか」の定義が変わる


## ④ 依存関係・DI・テストでの意味

```kotlin
class A(var p: Int)
```

- p は「外から与えられる依存」
- テスト時に差し替えやすい

```kotlin
class B {
    var p: Int = 0
}
```

- p は「内部状態」
- 外部から与える設計ではない


## まとめ

違いは「初期化タイミング」だけではなく、「そのプロパティがクラスの本質か、単なる内部状態か」

| 観点                  | A          | B        |
| --------------------- | ---------- | -------- |
| コンストラクタ指定    | できる     | できない |
| クラスの構成要素      | ○          | ×        |
| 不変条件を表現        | できる     | できない |
| data class に含まれる | ○          | ×        |
| 意味合い              | モデル・値 | 状態     |


Jetpack Compose / クリーンアーキテクチャの文脈では

- UI State / Domain Model → A
- ViewModel の可変状態 → B

を選ぶことが多いです。
