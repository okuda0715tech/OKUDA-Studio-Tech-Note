# 依存関係逆転の原則(DIP)

## 概要

高水準のモジュールは低水準のモジュールに依存すべきでない。


## 高水準と低水準とは

- 高水準とは
  - アプリでやりたいこと（ビジネスロジック）を意味します。
  - 具体的な実装では、ドメインレイヤーのユースケースなどを意味します。

- 低水準とは
  - ビジネスロジック以外の実装（ UI やデータの保存等）を意味します。
  - 具体的な実装では、 UI レイヤーやデータレイヤーを意味します。


## 具体的な実装方法

高水準のモジュールは低水準のモジュールに依存すべきでない。ということは、

例えば、 UseCase が Repository に直接依存するのではなく、 Repositoty はインターフェースを実装し、 UseCase はインターフェースに依存することで、 DIP を満たすことができます。

これにより、 Repository をテストデータに置き換えたり、保存先を別の方法に変更することが容易になります。
